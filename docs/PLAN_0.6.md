# 0.6: performance (the list)

Started 2026-10-23. The chain review of 2026-10-23 (OpenXR -> shim -> generator -> encoder -> Wi-Fi -> headset -> tracking) added items A to D below; the
NVIDIA engines that matter (three NVENCs through native split encode, the optical-flow engine, the realtime scheduling class) are already in use, so the
remaining wins are scheduling and fewer full-resolution passes. Checked and not pursued: AV1 (the Vision Pro's M2 has no hardware AV1 decode),
4:2:2 HEVC, DLSS frame generation (no headless API), FSR3 frame interpolation as a synthesis backend (SM time the GPU-bound game does not have,
where the optical-flow engine is free), NVENC external motion hints (quality, not speed), slice-level output (the client cannot take partial
access units), Reflex (needs a Present; item A is the same mechanism in our hands). Before adding to it, read what was already tried: docs/PERFORMANCE_FINDINGS.md (last section: the 1/2 cap in the rig,
OFXR-Bridge's pacing ideas) and docs/FG_REFERENCE_FRAMES.md (encoder references, parked). Ruled out without new evidence: non-reference
generated frames, a running-start lead cap, flow scale 0.25, a one-refresh buffer below the cap, GPU scheduling class 0, HAGS off,
just-in-time release.
