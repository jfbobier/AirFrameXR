# VisionALVR 0.4.0-alpha

Alpha software, test at your own risk. Streamer for ALVR headsets (Apple Vision Pro, Quest 3), NVIDIA GPUs with NVENC API 12.2 or later.

## Tested on

RTX 5090 with an Apple Vision Pro (ALVR visionOS app 20.14.x, 90 and 100 Hz) and a Quest 3 (Meta-store ALVR client, 90 Hz), frame generation
included on both; automated tests on an RTX 3080 Ti laptop. NVIDIA only, end to end: NVENC for the encode, NVIDIA Optical Flow for the
generated frames, DLSS motion vectors through the OptiScaler fork. No other GPU vendor is planned; fork and adapt if you need one.

> **Vision Pro: a plain green screen when the headset connects is normal.** It is the streamer's idle frame while no game runs. Set the ALVR
> app's chroma-key colour to pure green (#00FF00): the green becomes transparent, you see your room between games, and the game appears when it
> starts. If the headset stays green, the chroma key is not set. VisionALVR does not mirror the Windows desktop into the headset between
> sessions, by design.

## New: frame generation

For games that cannot hold the headset's display rate. The toggle **Frame generation** in the streamer window (and in Settings, `video.frame_gen`)
is off by default; nothing engages by itself, and the rate is fixed for a run. The game is paced to a fraction of the display rate and the
streamer generates the frames in between, every output rotated to the newest tracking sample so head turns stay as smooth as before:

- **Game rate 1/3, 1/2 (default), 2/3** (slider, `video.frame_gen_rate`): at 1/3 and 1/2 the game is locked to the display cadence (two or
  one generated frames per rendered one), at 2/3 it is held to two thirds of the rate and every frame sent is interpolated. 1/3 suits a game
  at 30-33 fps, 1/2 one at 45-50, 2/3 one at 60-66. Latency by construction: one game period (interpolation).
- **Recommended** (tick, on by default): the streamer records every game run of 20 s or more in `config\games.json` (per game, headset and
  rate: fps, the headset's own repeated display periods, the streamer's repeats, as the typical 10-second window and the heavy parts) and the
  launcher sets the rate from those records when the game starts: the fastest rate whose last run was clean, a clean run that filled its cap
  proposing the next rate once. No record yet: the slider stays yours. When a game ends the **Streaming** box shows the run's record and what
  will be proposed next time. Untick and the slider is yours. The streamer never changes the rate on its own.
- **DLSS motion vectors** (tick, `video.game_motion_vectors`, on by default): when the game runs DLSS and the
  [OptiScaler-DLSSMotionVectorExtractor](https://github.com/jfbobier/OptiScaler-DLSSMotionVectorExtractor) DLL sits next to its executable, the generator moves the scene with
  the game's own vectors (exact, no ghosting of fast objects); otherwise it measures the motion with the GPU's optical-flow engine (NVIDIA
  Optical Flow, Turing or later). Install the DLL: the zip carries it as `DLSSMotionVectors\dxgi.dll`; copy that file next to the game's real
  executable (Unreal titles: `Binaries\Win64\`), renamed `winmm.dll`, `version.dll`, `dbghelp.dll`, `winhttp.dll` or `wininet.dll` when another
  mod already owns `dxgi.dll`. No registry change, no ini. GPL-3.0, source at the fork's repository; the C interface is `DLSSVEC_*`, so an
  older `VisionALVR-OptiScaler` DLL is no longer found by this build (the shim then logs "no provider in the game": replace the file). The shim log confirms with `motion vectors:
  attached` and `-> shared copy` lines. Not compatible with Luke Ross's R.E.A.L. VR mods (they hook DLSS themselves) or anti-cheat titles;
  Unity's own DLSS path does not go through it. A game folder holding stock OptiScaler keeps working, without the vectors.
- **Uncapped** (config only, `video.frame_gen_rate: "uncapped"`, with `video.frame_gen_cap_fps` and `video.frame_gen_lag_ms`): the game runs
  free and every output is interpolated behind a content lag; for experiments, see docs/FRAME_GENERATION_UNCAPPED.md.

Measured on the RTX 5090 + Vision Pro: a 38-43 fps Unreal game at 1/3, 97-99 streamed fps for a 100 Hz panel with 0.5-2 % of the headset's
periods repeated and 67 ms of total latency (86 ms and 38-52 % repeated without generation); a 64 fps game at 2/3 for ten minutes, 1.6 %
repeated. Generator cost per output: flow 2.3-3 ms + synthesis 0.4 ms (1 ms with vectors). Known limits: the latency above; quad layers are
interpolated with the scene; a frame made only of quads (a menu) is passed through as it is.

**Perceived quality varies a lot from one setup to another, with generation on above all.** On one PC and one headset the same build felt
right one evening and wrong the next, and each time a condition of the setup was the cause: the Wi-Fi channel, the panel at 100 Hz instead
of 90 under 50 Hz lighting, the arrival margin before the headset's tick, the rate per game, a headset's tracking cadence mistaken for its
display rate. These are measured and mostly handled in this build; a new PC, router or headset will find the next one. docs/PERFORMANCE_KNOBS.md
lists every knob, its measured effect and what should drive it. Zelda: Breath of the Wild (Cemu + BetterVR) works fully in this build.

## Also in this release

- **Recenter**: a button in the streamer window, and sent at every game start: your forward at that moment is forward, your position the
  origin (the Vision Pro client centres itself at connection and agrees; the Quest passed the room's forward, which started one game facing
  the wrong way).
- **Eye-height override greyed out for headsets other than the Vision Pro** (they report their floor correctly); the saved value stays.
- **Display rate**: the streamer follows the panel's real refresh rate (the Vision Pro runs 90 or 100 Hz as visionOS decides) and only
  believes a cadence that is one of the rates the headset declares (the Quest 3 tracks at 270 Hz for a 90 Hz panel).
- **Frame arrival margin** before the headset's render tick raised from 3 to 7 ms (`VISIONALVR_PHASE_MARGIN_MS`): fewer frames shown a tick
  late, no measurable latency cost at the headset's own quantum.
- The streamer, configure and setup windows open centred.
- Headset-less lab (`harness/simrig`): in-scene motion judge next to the head-rotation judge, scenarios per rate, with and without vectors.
- Everything from 0.3 (setup wizard, Find headset, intake gate, foveated Vision Pro profile) unchanged.

Unzip over the previous folder or next to it; `config\visionalvr.json` and `config\session.json` are kept. The personal zip is not published.
