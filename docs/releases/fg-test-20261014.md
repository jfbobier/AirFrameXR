# Frame generation test build (branch fg/optical-flow, 2026-10-14)

Test build, not a release: the 0.3 streamer plus optical-flow frame generation (docs/FRAME_GENERATION.md). Release flavour (no
per-frame telemetry). Built on an RTX 3080 Ti; lab-verified headset-less (simrig) only. Headset verdict pending.

**Enable**: Settings, checkbox "Frame generation" (`video.frame_gen` in `config\visionalvr.json`, or `--frame-gen on` /
`VISIONALVR_FRAME_GEN=1` for the host). Off by default. Needs an NVIDIA GPU with the optical-flow engine (Turing or later; the host
loads the driver's `nvofapi64.dll`). When on, the game runs at half the display rate and the host sends an interpolated picture
between every two rendered frames; one display period of added latency.

**What to check first**: head still, look at the horizon, then turn slowly: any tremble means the Vision Pro dislikes re-stamped
frames (every output is stamped with a fresh tracking sample and rotated to it). Then a game that stutters at 50-70 fps: in-scene motion
(driving forward, objects passing) should be smooth; HUD elements and particles may ghost or dim in the generated frames (known limit).

**Telemetry**: `encoder_stats.pipeline.frame_gen` in the stats (synths, reals, repeats, queued, arrival waits, flow and synthesis GPU
milliseconds under `gen`); event `frame_gen` at start with the engine info.

Asset: `VisionALVR-fg-test-<commit>.zip` (the generic package; sha256 in the release notes on GitHub).
