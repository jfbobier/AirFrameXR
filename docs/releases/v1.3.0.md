# AirFrameXR 1.3.0: Black Box, a performance flight recorder

**The focus of this release is the new Black Box performance suite.** The streamer itself is unchanged from [1.2.0](v1.2.0.md): this release adds a way to find out *where the
time goes* in a game that does not run well, without touching how you normally stream.

![AirFrameXR Black Box](../../branding/blackbox/banner/blackbox-banner.png)

## What Black Box is

Two programs, because it is two tasks, started on purpose when a game stutters:

- **Black Box Recorder** (`blackbox_recorder.exe`): your streamer window with a recording panel. It copies your normal streamer's settings and headset pairing when it starts (one way:
  your normal folder is never written), then records on a key (**F8** by default, configurable; the game does not see the key) or for a **full session** (from the game's start to its close,
  for games where the problem comes late). While it records it samples the GPU (utilisation, clocks, power, temperature, VRAM, limiter, encoder) and the Windows counters (CPU, memory, network,
  GPU engines of the game and the streamer), and keeps the streamer's per-frame files, into `logs\performance\<time>_<scene>\`. An optional **Deep trace (admin)** button records GPU and CPU
  scheduling for 20 s with Windows' own recorder: one permission prompt, declining changes nothing. This is the only thing in the suite that can ask for administrator rights.
- **Black Box Analyzer** (`blackbox_analyzer.exe`): nothing is analyzed until you click. It says where the time went (the game, the encoder, the sender, the GPU limiter), shows the worst
  10-second windows of a long session and the worst late frames with the stage that made each one late, replays old recordings, exports, deletes (one or the old ones) and opens a recording
  from another PC (folder or zip). It refuses to analyze while a recording runs, so it never competes with the game for the CPU.

Most late frames come from the game (DLSS quality, ray tracing, resolution), so the report names the game as the limit when the stream waited for it and the GPU was busy.

## What is in the download

`AirFrameXR-1.3.0-bundle.zip`: the normal package, unchanged, and the Black Box in `bench\telemetry\` (a complete second install built from the telemetry build, with its own
launcher; nothing is shared with the normal one at run time, only the settings it copies). Start the normal streamer with `AirFrameXR.exe` as before; for a diagnosis start
`bench\telemetry\AirFrameXR.exe` instead (close the normal streamer first: one headset, one port). The telemetry build logs per frame and costs CPU, which is why it is separate:
the normal package never carries it and never asks for administrator rights.

## Lab results and what is not tested

Lab (RTX 3080 Ti laptop, 2026-10-30): the probe, the report (11 generated sessions with known faults and known non-faults, byte-identical output on a second run), the recorder's file cut and
settings round trip, and the GUI matrix (405 renders at 1080p / 1440p / 4K and 100-200 % scale, 0 failures) pass. The probe's own cost against the pacing lab (3 runs per condition):
at 1 Hz invisible; at 5 Hz with 75 GPU-engine counters p95 +0.25 ms and max +4 ms, p99 and late frames inside the noise. The normal package was checked to contain no Black Box file and a
host and shim without the telemetry code.

**Not tested: a recording with a real headset and a real game** (F8 against your games, a full session, the beep in the headset, the Deep trace's permission prompt and Windows' profile names),
the RTX 5090, and the report's numbers against the older `harness/frames.py` on the same window (on the first real session it counted 1.72 % late frames where `frames.py` counts 17 of 9412 on its own
subset: the windows differ, the comparison is owed). Treat the verdicts as a first reading, not a measurement standard, and tell us what you see. Use at your own risk, see the README.
