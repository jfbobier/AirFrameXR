# AirFrameXR 1.4.2: neural frame generation

Frame generation now builds each in-between picture from the motion a neural network sees between two game frames: RIFE 4.4, run by our own
CUDA code inside the streamer. Moving objects come out with fewer double images and torn outlines than with 1.4.1's optical-flow synthesis; still
content stays exact. How it works: `docs/FRAME_GENERATION.md` ("Neural fields"); the network, its build and its checks: `docs/NEURAL_RIFE_CUDA.md`.

## What is new since 1.4.1

**Neural frame generation, on by default.** For each pair of game frames, RIFE 4.4 computes at half the eye's resolution where every part of
the picture moved and how to blend the two frames; the streamer's own pass composes the picture at full resolution from one sample of each
frame, with the head rotation removed first as before, the camera turn (stick turns) kept, and still content copied as is. In the lab, against
frames really rendered at the in-between moment: +0.91 dB on moving edges over 60 cases (walking at 1-2 m/s: +2.3 to +3.9 dB), +1.04 dB at the
Vision Pro's stream size, fewer double images, slightly softer. The author on the RTX 5090 (an earlier build with the same network, Hellraiser,
Gears of War E-Day): "clearly better", "sharper".

- **Cost:** about 1.8 ms of GPU per game frame pair at the Vision Pro's stream size on the 5090 (on the shader cores the game also uses), about
  0.3 ms of CPU. The optical flow keeps running (the camera turn measures from it).
- **Every rate:** at 1.5x and 3x each generated picture uses fields computed for its own moment (an earlier build reused the midpoint's and
  shook on menu text).
- **Needs an RTX 30 series or newer.** On older NVIDIA GPUs, or without the network's files, the streamer uses 1.4.1's synthesis by itself.
- **Small:** the network is 11 MB in `bin\neural` (`airframexr_rife.dll` 0.7 MB, `rife44.afxw` 10.5 MB of weights). No TensorRT, no Python;
  CUDA comes from the NVIDIA driver.
- **Your choice in Advanced** (Frame generation, *Generated-frame synthesis*): **neural** (the default) or **edge**, 1.4.1's synthesis from the
  GPU's optical flow, as a fallback (classic and edge-blend stay).
- **Logs:** the neural lines (enabled or why not, runs and timings per window) are written in debug mode only.

Licences: RIFE 4.4's weights (MIT, Practical-RIFE by hzwer; vs-rife's model code, MIT) and NVIDIA CUTLASS (BSD-3-Clause), compiled into the
DLL; texts in `docs\licenses`.

## What ran, and what did not

**Lab (RTX 5090, driver 621.24):** the network against PyTorch on real frame pairs (closer to the full-precision model than PyTorch's own
half-precision run); the frame generation judge at both lab sizes and at the 1/3 output time; the streamer path with the probe app at 2x and
1.5x (`e2e_fg_neural`, `e2e_fg_neural_23`: every generated frame composed from the fields, 0 failures, 90 fps held).

**Headset:** the author played an earlier build of the same network (run by NVIDIA TensorRT for RTX) on the 5090: better than 1.4.1's
generation; the 1.5x / 3x shake found there is fixed. This build's own code has not been played yet.

**Not run:** any GPU other than the 5090 (the RTX 30 / 40 code is built, never run), a GPU-bound game's frame rate with and without the network,
the Quest, the stability harness.
