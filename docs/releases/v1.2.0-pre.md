# AirFrameXR 1.2.0 (pre-release, branch `fov-restriction-aware-engine`)

Everything in [1.1.1](v1.1.1.md), plus the field-of-view work of 2026-10-29 (`docs/FOV_PIPELINE_OPTIM.md`, `docs/FOV_CLIENT_CEILING.md`):

- **The FoV grid ships in the package**: `bench\fovgrid.bat` (and `bench\fovgrid.exe`) shows a head-locked grid in true angles through AirFrameXR like a game,
  with a white border at the edge the headset declares, so you can see how much of the picture your headset shows and tune the Advanced window's
  field-of-view fields yourself; `fovgrid.bat 0.96,0.71,0.69,0.61` draws that rectangle on the grid to check a calibration before or after entering it
  (`docs/FOV_GRID.md`). The calibration bundle (`tools/fov_calibration_bundle`) now runs the fixed-gaze pass after the following pass.
- **"Fit the stream to the headset's window"** (Advanced picture and FOV settings, `video.stream_fit_window`): the stream frame sized to the box the headset
  declares at the pixel density of the resolution you saved, written into `session.json` (streamer restart); when the headset declares a new box the streamer
  window recomputes it and says a restart applies it. With the AirFrameXR client declaring the calibrated window, 3552 x 3200 over the full box becomes
  3168 x 2496: 30 % fewer pixels on every stage and, on the full-frame profile, 30 % fewer encoded pixels (13 % on the foveated profile at an equal foveal band),
  measured on an RTX 3080 Ti: encode 11.3 -> 8.4 ms foveated, 20.2 -> 15.4 ms full frame, frame generation -30 %. With the client declaring the generous
  ceiling instead (the client build of `docs/FOV_CLIENT_CEILING.md`), the tick saves about 6 %. Off by default.
- **Render quality up to the saved resolution**: with the fit on, the Game render quality slider's right end is the resolution you saved (the panel reference),
  not the fitted stream's size, so a restricted game can still be told up to 3552 x 3200 for supersampling. IPC version 36 carries it.
- **What the pipeline will do**: the Advanced window shows, under the FoV fields, the stage sizes the current settings imply (game render, stream frame, encoded
  frame, NVENC strips) and warns when NVENC's split-frame encoding will not engage: the automatic mode splits only frames 2112 rows or more with the P1-P4
  low-latency presets (NVENC SDK guide 13.0, 8.14), so a foveated frame (1664 rows today) only splits with the forced mode; the forced mode is the default.
- **Frame pipeline in Game statistics**: each run's record now carries what every stage did (declared box, rectangle, game render size, stream, encoded frame,
  foveation, generation, strips expected and seen, encode p50 / p95, foveation-pass and compose times), drawn as a row of tiles; a split that did not engage is named.
- **The override survives a client update**: the "override saved for another headset" guard keys on the headset's name, so the saved calibration stays applied
  when the headset app declares another box (the client ceiling).
- The host writes `config\airframexr_gpu.json` (GPU, driver, NVENC engines, split conditions) at every encoder creation.

Lab (RTX 3080 Ti, 2026-10-29): the FoV scenarios old and new (12) and the OpenXR chain on the new IPC PASS, the launcher's pipeline model equals the Python oracle on
148 cases, the GUI matrix rows PASS. **Not on a headset**: the fitted stream's picture, the foveation band presets, the split strips at the shrunk size (a 5090), the
client ceiling build. IPC version 36: host, shim and package must come from the same build. Use at your own risk, see the README.
