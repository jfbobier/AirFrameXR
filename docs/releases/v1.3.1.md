# AirFrameXR 1.3.1: Black Box, better verdicts, charts and a safer OpenXR switch

The streamer is unchanged from [1.3.0](v1.3.0.md) and [1.2.0](v1.2.0.md). Everything in this release is the **Black Box performance suite**, improved after the first recording on an RTX 5090
(Assassin's Creed Black Flag, frame generation, 100 Hz, Apple Vision Pro). **Update the Black Box if you use it; the normal streamer needs nothing from this release.**

![AirFrameXR Black Box](../../branding/blackbox/banner/blackbox-banner.png)

## What was wrong in 1.3.0, and is fixed

The first real recording showed that the 1.3.0 report could mislead:
- It said **"late gaps: mostly upstream, lower the game's settings"** on a frame-generation session. Under frame generation a frame's arrival time is its *source* frame's, so the game's own cadence was read as lateness.
  The late frames actually came from the encode window (the encoder used 105 % of the frame period at the 99th percentile) while the GPU itself sat at 52 %. The wait for the encoder is now measured from the host's display
  boundary for every frame, and "upstream" means the game's arrival gap for a game frame and the host's own clock slip for a generated one.
- It showed a **GPU limiter active 100 % of the time** with an empty name: the RTX 5090's driver keeps an undocumented clock-event bit (0x400) set. Only the documented limiter bits count now; any other bit is named and not counted.
- It showed the NVENC engines as **"188 %"** without saying it was the sum of three engines.
- The OpenXR runtime switch used the normal install's register script, which also replaces the normal install's firewall rule and forgets the runtime it replaced (see below).
- **Correction to the 1.3.0 notes and README**: they said only the optional Deep trace asks for administrator rights. Switching the OpenXR runtime asks too (the setting is machine-wide). Both are declinable and the recorder explains them.

## What is new

- **Results by resource, in bottleneck order**: **GPU, CPU, memory and I/O, network, VR rendering**, one block each, with metrics in two columns (**average** and **worst**: the 99th percentile of a load, the lowest value of a clock, of free
  memory or of an fps) and a status per category. A category is a PROBLEM only when the stream really had more than 1 % late frames and that resource shows the evidence; VR rendering is the symptom and is never named as the cause.
  The new GPU rows include the encoder's share of the frame period, the game's and the streamer's GPU engines, the compose pass and frame generation's optical flow; new counters give the game's and the streamer's CPU (in cores),
  memory and file reads, disk throughput and latency, and hard faults.
- **A fixed verdict** that names the first category with evidence in that order: "Late frames 2.98 %. GPU: the encoder uses 105 % of the frame period at the 99th percentile ...". "Smooth" when late frames are under 1 %, whatever the sensors say.
- **A time series per category** on a shared time axis, with a late-frame strip against the 1 % budget on top. Every line is drawn as a percentage of its own limit (the frame period, 100 % load, all the cores, all the RAM, the display
  rate), so different units share one scale; hover for the real values in every chart at once.
- **The OpenXR runtime, explained and reversible.** A game loads Windows' active OpenXR runtime, so to record a game the Black Box must be that runtime while you record. The recorder says so at start, offers the switch, remembers
  exactly the runtime it replaced (your normal AirFrameXR, if that was it) and a **Put back ...** button restores it (also offered when you close the window). It sets one registry value and nothing else; the normal install's firewall
  rule and saved state are not touched. Each switch asks Windows for administrator rights.
- **A cleaner folder**: `blackbox_perf.exe` in the root starts the Black Box, which lives in `blackbox\` (`bench\` keeps only the small benches: the scene, the FoV grid, the probe).

## What is in the download

`AirFrameXR-1.3.1-bundle.zip`: the normal package (release build, unchanged) with the Black Box inside it. Start the normal streamer with `AirFrameXR.exe` as before; start `blackbox_perf.exe` for a diagnosis (close the normal
streamer first: one headset, one port). The normal package contains no Black Box code and never asks for administrator rights.

## Tested and not tested

Lab (RTX 3080 Ti and RTX 5090, 2026-10-30/31): the report against 13 generated sessions with known faults and non-faults (including frame generation and an unknown limiter bit; byte-identical output on a second run), the probe's files and
the new counters, the recorder's file handling, the corrected report on the real 5090 recording equals an independent calculation (262 late frames from encode time, 51 from the wait for the encoder, 44 from the host's clock slip, out of 357),
and the GUI matrix (405 renders at 1080p / 1440p / 4K and 100-200 % scale: 0 failures, 0 warnings).
**Not tested**: the OpenXR switch's permission prompt and put back on a real machine, F8 in real games, the beep inside the headset, the Deep trace's permission prompt, the chart hover in a live window, and a recording made through the
new panel. Treat the verdicts as a first reading and tell us what you see. Use at your own risk, see the README.
