# AirFrameXR 1.1.1 (pre-release)

Everything in [1.1](v1.1.0-pre.md), plus two switches for games whose frame loop upsets the stream, found with Assassin's Creed Black Flag (Resynced, UEVR-based VR mod):

- **Game fps lock** (Advanced > Arrival and pacing, `video.frame_gen_cap_fps`). The cap used to apply only in uncapped frame generation; it now holds the game to that many frames per second in every mode. Off (0) by default. **Change:** a cap stored in `airframexr.json` from an earlier version now acts in the other frame generation modes too; set it to 0 to keep the old behaviour. With the headset at 90 Hz, 45 (or 30) divides evenly; at 100 Hz use 50.
- **Game frame pacing fix** (Advanced > Arrival and pacing, `video.drop_duplicate_frames`, restart to apply). Some VR mods submit every real frame twice (a second wait / begin / end that resubmits the same layers with the same poses), so the game's second wait costs a whole display period and the real frame rate halves. With the tick on, the shim recognises that pattern (one or two identical re-submits per real frame, confirmed over windows of 40 submits), drops the duplicates and answers the second wait at once. Measured in the field on that game: 25 to 31-34 real frames per second, late releases 70 % to 4 %. It acts only on a confirmed duplicate pattern: a normal game, a stationary pose, or a pattern that stops are left alone. **Off by default and then nothing differs from 1.1** (a lab scenario proves it). Inspired by UEVR's native stereo fix.
- **Not fixed**: that mod's own change of rhythm about 4 minutes into a session (at engine frame 12,000 its submit thread pool shrinks from about nine threads to one) still happens; the lock evens out its effect.
- **Lab**: `xr_modsim`, a mimic of that mod's frame loop (pool of submit threads, double submit, engine-time changes), with scenarios for the fix off, on, with a normal game, with triple submits, a duplicate pattern that stops, a stationary pose, and the rhythm change under GPU load. The installed-layout scenario starts from the package defaults (a personal `airframexr.json` left in the builder's folder had restricted its field of view) and the desktop-mirror scenario is BLOCKED, not failed, where the screen cannot be duplicated. A generic package no longer ships a stale `config\airframexr.json`. Whole suite with the fix forced on: 43 of 46 passed, the other three explained in `harness/README.md` terms (two oracle problems since fixed, one start-up flake).

IPC version 35: host, shim and package must come from the same build. The hardened pacing fix has not run on the headset yet (the field results above come from the build before the hardening). Frame generation needs an NVIDIA RTX GPU (Turing or later). Use at your own risk, see the README.
