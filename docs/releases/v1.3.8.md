# AirFrameXR 1.3.8: a revamped interface, OpenComposite for OpenVR games, honest bitrate and latency tiles, negative foveation shifts reach the encoder

The engine is [1.3.7](v1.3.7.md)'s plus one fix in the host; the rest is the interface and what ships next to it. First published as the pre-release `v1.3.8-pre.1`.

## What is new

- **Fix, host: a negative foveation centre shift is applied.** The host set each foveation value only when it was above 0, so a negative centre shift (which the 1.3.7 session compile can produce from the headset's picture edges) stayed at the host's defaults 0.4 / 0.1 while the headset was sent the real value: the host compressed with one map and the client decompressed with another. Found by the new `e2e_session_compiled` harness scenario (the stamp in the decoded stream sat where the oracle puts it for 0.4 / 0.1). The shift is now taken as it is (zero and negative included); sizes and ratios still must be positive. In the field logs we have (shift 1.0 / 0.178) it did not occur; it does with other picture edges.
- **Launcher tiles.** A run's bitrate and throughput are medians of its 10-second windows (one absurd window showed 6801 Mbps for a 275 Mbps stream; the windows themselves were already medians since the commit before). The Latency tile shows what the number is: ALVR's total from the head pose to the picture, split as enc + net + dec + game and queues (ALVR's "network" is the remainder after its other parts, not a measurement).
- **UI revamp (validated 2026-11-10).** Streamer: three live tiles with the streamed fps, bitrate and packet loss on one line, a **Features** box (frame generation and the desktop mirror in one aligned column of switches), rates named **x1.5 / x2 / x3** (the settings keep `two_thirds | half | third`), **Auto off by default**, a menu in the header instead of the Main menu button, one shared notice line (the audio note is only in the log now). Launcher: two small switches, **OpenXR runtime** and **OpenComposite (OpenVR) translation**. Advanced window: the game fps lock, the pacing fix, the stream size and the field of view on top, the rest under an *Experimental* fold. Game statistics: the frame drawn from the game to the headset with the latency split, trend charts over the sessions, and the last run over time from the general log.
- **Headset-neutral setup and tests.** The wizard, the tests and the find dialog say "the headset app" (the stock ALVR app or the AirFrameXR client) instead of "the ALVR app on the Vision Pro"; Vision Pro statements (refresh-rate advice, resolution note, field of view help) only appear where they apply; one function guesses a headset's name from what its app announces; the interface matrix has Quest 3 wizard pages.
- **OpenComposite ships** (limited OpenVR support): the project's own prebuilt DLLs (GPL-3.0-or-later, revision `a27e7e6`, unmodified) in `opencomposite\` with their source and licences; the launcher switch only points the system-wide OpenVR runtime path at them (and back at SteamVR). Not yet run with an OpenVR game.
- **GUI layout**: two rows clipped at some scales (the supersampling tick in the field-of-view panel, the resolution note in Settings) are fixed; `ui_matrix` 504 renders, 0 FAIL.
- **Docs**: `docs/VISIONOS_TELEMETRY_LEARNINGS.md` findings 10 and 11: the client loses about 0.1 % of frames, "repeated periods" is the stream's delivered shortfall, not client drops.
- **Lab**: the harness can run the streamer's own session compile (`harness/sessioncompile.py`, scenario `e2e_session_compiled`); window-driving tests follow the golden master; mock-client latency model and pacing scenarios.

## What ran, and what did not

Host unit tests 12 of 12 (including the shift and the median tests). On the 3080 Ti builder: `e2e_session_compiled` passes (stamp readback, 0 counter mismatches); the full `ui_matrix` (nine sizes and scales, 56 renders each) passes with 0 FAIL and 0 warnings; `streamer_events`, `advice_check`, `export_logs`, `opencomposite_check` (the shipped DLLs' hashes and the switch, in a temporary folder) and `log_timeline_check` (the last run read from a real log) pass; the package builds with the OpenComposite files in it. Earlier standalone check chain (2026-11-09): all passed except `fov_store_check` (`over_declared_red`, known, not from this release) and the audio checks (builder cable name, not run).

**Not run:** the new interface and the engine on a headset session in this build; **OpenComposite with a real OpenVR game** (the DLL folder layout is taken from the project's own switcher; try one game and switch it off again if it does not start); `launcher_flow` ends with one harness failure (it cannot read the launcher's exit code `-1` on the first tool of a run; the log shows the hide and return working).
