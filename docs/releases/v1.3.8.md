# AirFrameXR 1.3.8 (pre-release): negative foveation shifts reach the encoder; honest bitrate and latency tiles

The engine is [1.3.7](v1.3.7.md)'s plus one fix in the host. Pre-release: tried on the owner's headset before a release.

## What is new

- **Fix, host: a negative foveation centre shift is applied.** The host set each foveation value only when it was above 0, so a negative centre shift (which the 1.3.7 session compile can produce from the headset's picture edges) stayed at the host's defaults 0.4 / 0.1 while the headset was sent the real value: the host compressed with one map and the client decompressed with another. Found by the new `e2e_session_compiled` harness scenario (the stamp in the decoded stream sat where the oracle puts it for 0.4 / 0.1). The shift is now taken as it is (zero and negative included); sizes and ratios still must be positive. In the field logs we have (shift 1.0 / 0.178) it did not occur; it does with other picture edges.
- **Launcher tiles.** A run's bitrate and throughput are medians of its 10-second windows (one absurd window showed 6801 Mbps for a 275 Mbps stream; the windows themselves were already medians since the commit before). The Latency tile shows what the number is: ALVR's total from the head pose to the picture, split as enc + net + dec + game and queues (ALVR's "network" is the remainder after its other parts, not a measurement).
- **GUI layout**: two rows clipped at some scales (the supersampling tick in the field-of-view panel, the resolution note in Settings) are fixed; `ui_matrix` 504 renders, 0 FAIL.
- **Docs**: `docs/VISIONOS_TELEMETRY_LEARNINGS.md` findings 10 and 11: the client loses about 0.1 % of frames, "repeated periods" is the stream's delivered shortfall, not client drops.
- **Lab**: the harness can run the streamer's own session compile (`harness/sessioncompile.py`, scenario `e2e_session_compiled`); window-driving tests follow the golden master; mock-client latency model and pacing scenarios.

## What ran, and what did not

Host unit tests 12 of 12 (including the shift and the median tests). On the 3080 Ti builder: `e2e_session_compiled` passes (stamp readback, 0 counter mismatches), `ui_matrix` 504/0, `streamer_events`, `performance_check`; the standalone check chain of 2026-11-09 passed except `fov_store_check` (`over_declared_red`, known, not from this release) and the audio checks (builder cable name, not run). **Not run on a headset.** The tile fixes were checked by unit tests and the GUI harness, not on a long real session.
