# AirFrameXR 1.3.2: calibrate the field of view yourself

The streamer is unchanged from [1.3.1](v1.3.1.md) except for the version number. This release adds a guided **eye calibration** for the field of view the games are told, and fixes the shipped Vision Pro profile.

## What is new

- **Calibrate / restart headset setup** (launcher card, formerly "Restart headset setup") now opens a step with two buttons: **Eye calibration wizard (30 min)** and **Setup wizard**.
- **Eye calibration wizard** (`bin\calibrate.exe`): a dot drifts outward in 24 directions per eye and you click when it is gone, twice (eyes following, then eyes fixed). It needs the streamer open and the headset
  connected (it starts the streamer itself, minimized, if it is not running), and turns the field of view override off if it is on. It then draws your measured window (the 24 rays, where the square vanished on each, the outline) and the smallest rectangle that covers 99 % of what you saw (100 % and 97 % are one click away) and **Use this field of view** applies it;
  **Save a copy...** writes it as a profile file to share. Earlier runs are kept and used together (the larger window wins); incomplete runs are discarded; a missing pass, a single run or a big spread between runs
  gives a warning; too little data is refused. Details: [FOV_CALIBRATION.md](../FOV_CALIBRATION.md).
- **Import a calibration file...** in *Advanced picture and FOV settings* installs such a file and applies it. A calibration file carries only a field of view (no stream settings), so it never replaces the stream
  settings of your headset's profile ([HMD_PROFILES.md](../HMD_PROFILES.md)). The wizard's *Import profile...* accepts it too and applies only the field of view.
- The calibration bundle's `run_sweep.bat` now ends by writing the same profile file (`fov_profile.exe`).

## Fixed

- The shipped **Apple Vision Pro profile never loaded**: its network variant sat inside the `fov` block and the file had no `network` entry, so the profile parser skipped it. It loads now, which means the wizard
  proposes its stream settings (3552x3200, 90 fps, 300 Mbps, foveated, split encode 3) and its ALVR settings for a Vision Pro, and the Advanced window offers its measured field of view.

## What was tested, and what was not

- **tested-pass** (on the PC, no headset): the fit gives the same rectangle as the analysis script on the second wearer's sweeps (1.00 / 0.89 / 0.92 / 0.82 against 1.00 / 0.89 / 0.91 / 0.82); the generated file
  and the fixed Vision Pro profile parse as intended; the GUIs compile.
- **Not tested**: the calibration window on a headset (probe start, click counting, second pass, applying), the two import buttons, the new launcher step, what the wizard proposes on a real Vision Pro now that its
  profile loads. Please report what you see.
