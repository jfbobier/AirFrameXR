# AirFrameXR 1.3.7: the streamer's session is compiled at every start; Vision Pro default 3648 x 3200; two field-of-view profiles

The engine is [1.3.6](v1.3.6.md)'s (the host differs by its version number). 1.3.7 is the launcher's settings structure, a new default and a second Vision Pro field-of-view profile.

## What is new

- **Settings are separated from what the streamer reads.** `config\session.base.json` is the golden master of the ALVR settings and the only session file the windows edit (wizard, Settings, profiles, pairing). `config\session.json` is now transient: the launcher compiles it from the master, `airframexr.json` and the headset's declared box before every streamer start (stream fit, stream size for the bitrate, foveation from the picture edges). The field-of-view restriction, the fit and the bitrate no longer change the resolution you chose; they change the compiled size, at every start. A hand edit of `session.json` is lost at the next start on purpose. How it works: [ARCHITECTURE.md](../ARCHITECTURE.md), "Settings: golden master and compiled session".
- **Upgrading** needs nothing: a folder without `session.base.json` gets one from its `session.json`, with the stream size put back to the resolution you chose (the old fit had written its own size over it).
- **Pairing**: a headset ALVR trusted while the streamer ran is taken into the master at the next start (as Disconnected); a pairing made in a window after that wins.
- **Vision Pro default resolution 3648 x 3200** (was 3552 x 3200): Apple's panel is 3660 x 3200 per eye, aligned to ALVR's 32 pixels. The stream is still sized for the bitrate unless you type a size or fit it to the window, so at 300 Mbps the stream stays near what it was; the new number is the resolution the wizard proposes and the reference of *Spend the savings*.
- **Two field-of-view profiles for the Vision Pro**: *AVP optimized performance* (the former *AVP optimized*, 0.97 / 0.71 / 0.69 / 0.63) and *AVP optimized quality* (1.22 / 0.81 / 0.90 / 0.77: fewer black margins, about 1.5 times the game pixels). Fresh installs get both; an install that has the old entry keeps it under its old name and receives the new one.
- A profile's `match.default_view_resolution` can list several panel sizes (the Vision Pro profile matches the 3660 x 3200 the next client declares and the 3776 x 3648 of the builds in the field).
- **Fix**: starting the calibration twice within a few seconds (a second click) started a second fit scene and saved two identical profiles. A second start is now ignored while the first is launching.

## What ran, and what did not

The GUIs compile (`check_gui.sh`). `harness/session_compile_check.py` (new) passes its 7 cases on the 5090 build PC: the fit size compiled while the master keeps the chosen size byte for byte, a typed size kept, a hand edit lost, a pairing taken or kept, an old install migrated, a second compile changing nothing. Also pass on the 5090 build PC: `pipeline_model_check` (148 cases), `milder_check`, `render_plan_check`, `ratemap_check`, `fov_profile_check` (its profile counts updated for the second profile) and `ui_matrix --only advanced-switches` (9 renders, 0 FAIL: the check that would have caught the 1.3.6 hotfix). `fov_store_check` has one failing line, `over_declared_red` (a typed field of view wider than the declared box is rated Strange, 0.94, where the check expects Invalid, 1.00): it fails the same way on the 1.3.6 `main`, so it is not from this release, and it is not fixed here. **Not run on a headset**, and the launcher's whole start (compile, audio step, host) was not run end to end for this release. The 3648 x 3200 default comes from Apple's published panel size (iFixit / UploadVR teardown) and the rate map in the profile; the stream at 3648 was not measured.
