# AirFrameXR 1.5.3: one Settings window, and our own OpenComposite for OpenVR games

The streaming engine is 1.5.2's (the host differs only by its version string). What changed is the setup and settings windows, and the
OpenVR translation layer that runs old SteamVR games without SteamVR.

## Setup and settings

**One Settings card.** With no headset paired, Settings opens the setup wizard. Otherwise it opens two tabs: **Manual settings**, where you
can type the headset's IP address, and **Settings assistance** (Check my setup, Run the setup wizard again, and the single tests). The
launcher's "Diagnostics and headset setup" card and the Headset tab, which duplicated the headset discovery, are gone, as are the two
"Experimental" badges and the Logging checkbox.

**Advanced settings, grouped by intent:** Stream size, Frame rate and frame generation, and Game compatibility up front; the encoder, latency
and pacing internals folded below. The compatibility mode's text is rewritten.

**Meta Quest:** pairing a Quest preloads 2064 x 2208 at 90 Hz before the handshake, the size the scene test uses. The scene test recentres
1 s after it first places the scene, and on F8.

## OpenVR games: OpenComposite for AirFrameXR 1.0

The package now ships our fork of OpenComposite,
[airframexr-opencomposite](https://github.com/jfbobier/airframexr-opencomposite) ([release v1.0](https://github.com/jfbobier/airframexr-opencomposite/releases/tag/v1.0),
GPL-3.0, with its source in `opencomposite\`), instead of upstream's 2025 build. Upstream has merged nothing since July 2025; the fork adds:

- **Upstream fixes still waiting there:** newer OpenVR interfaces (No Man's Sky and Batman: Arkham VR asked for them and did not start),
  Half-Life: Alyx's start, frame timing measured instead of fixed numbers (games that scale their resolution from it, like Half-Life: Alyx,
  stayed at one level), Unity 2018 games' flipped double-wide textures, controller bindings (dpad in every action set, a double-click
  counted once), a crash in F1 23's frame timing call.
- **Games that start OpenVR twice.** ARK and ADE (Unreal) starts a second, background OpenVR client next to its game: OpenComposite stopped
  with "unsupported apptype 3". The second client now shares the running session.
- **Textures:** float formats and 10-bit or 16-bit textures marked as gamma-encoded no longer abort the game. When the OpenXR runtime has no
  swapchain format for them (AirFrameXR's offers 8-bit and 16-bit float), a small draw converts. D3D12 games: flipped textures no longer
  give an image the runtime rejects, and the copy waits for the game's rendering as D3D12 requires. D3D11: the game's render state is put
  back after such a draw.
- **The GPU:** D3D games are told which GPU the runtime renders on, as SteamVR does (it matters on a PC with two GPUs).
- **Built for speed:** whole-program optimisation, no CPU-specific instructions.

**The launcher's OpenComposite switch tells the truth.** OpenVR loads the first runtime in its list, and SteamVR puts itself back in front
whenever it starts: the switch said on while games loaded SteamVR. It now reads on only when OpenComposite is first, and turning it on
puts it first again.

**Games with Easy Anti-Cheat may refuse it.** OpenComposite's DLLs are not signed; Star Wars: Squadrons then hides its VR option (the game
never loaded our DLL). For such games, use SteamVR with stock ALVR.

## Tested

- **OpenVR games on the author's RTX 5090 with an Apple Vision Pro (2026-11-27/28), through the fork:** Moss and ARK and ADE played (ARK and
  ADE 2 min 57 s, 96 fps rendered, the second client shared as designed); Moss: Book II and Pistol Whip ran through it and streamed at about
  100 fps (the fork's earlier build, without the second-client fix and the optimisation flags). Star Wars: Squadrons: no VR option (above).
- **`opencomposite_check` on the 5090:** 13 of 13: the shipped DLLs and source archive are the ones `opencomposite\SOURCE.txt` states, and the
  switch (on, off, twice, SteamVR back in front) in a temporary folder.
- **The new Settings and launcher windows:** opened by the author on the 5090; the UI matrix (all windows and wizard pages at 9 display
  cases, Vision Pro and Quest) 603 renders, 0 failures.
- **The release build (2026-11-28, the 5090):** `harness/bundle.py` (the streamer, personal and Black Box zips; it now also builds the
  probe and the desktop mirror, which the package used to take from an older build). The zips checked: release build in the streamer
  zips, the telemetry build in the Black Box, the host and the windows say 1.5.3, `opencomposite\` holds the fork's DLLs and only its
  source archive (the first bundle also carried upstream's old one; the package now ships only the archive `SOURCE.txt` names), no
  settings or addresses in the public zip, and the same file list as 1.5.2's apart from that archive. The Advanced settings window:
  `ui_matrix.py --only advanced-switches` 9 of 9, and the packaged `configure.exe --switches` opened it with no error.
- **Not tested:** the fork's float-format and D3D12 paths (no game at hand uses them), Half-Life: Alyx, No Man's Sky, F1 23; the Quest
  preload and scene recentring on a Quest; a typed IP address reaching a headset; `launcher_flow.py` (updated, not run).
