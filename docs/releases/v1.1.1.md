# AirFrameXR 1.1.1

Everything in [1.1](v1.1.0.md). **Profile and docs only: the binaries are those of 1.1.0** (the app and the logs still say 1.1.0; IPC version 35 as before).

- **The Vision Pro field of view, corrected.** The 1.1.0 values (0.71 / 0.59 / 0.61 / 0.57) came from a sweep with the eyes following the dot only. Played in a game they left a black strip at the right eye's outer edge: with the eyes looking forward that eye sees 43 to 47 degrees outward, not the 35.5 the following sweep found. The profile now carries **0.96 / 0.71 / 0.69 / 0.61** (outer / inner / upper / lower tangents, 43.8 / 35.4 / 34.6 / 31.4 degrees), one mirrored rectangle for both eyes covering 99 % of the larger of the two eyes' windows over **both** gaze states (following and fixed), margin 0, render quality 0. The Advanced window's button "Use the Apple Vision Pro's measured values" fills them. It is still a button: nothing is restricted until you press it or tick the override.
- **A correction to the 1.1.0 notes.** They said the game renders "about a quarter of the pixels of the headset's declared view". That is against the stock app's declared 1.79 / 1.02 / 1.22 / 1.02 frustum. The AirFrameXR client declares its own visible limit instead (about 0.94 / 0.93 / 0.90 / 0.76), and against that the 1.1.0 values rendered about 48 % of the pixels and these render **about 68 %** (computed from tangent areas, not measured as frame time). So this release trades some of the saving for no black at the edges. Against the stock frustum: about 35 %.
- **Tested:** the author played a game on a Vision Pro with these values: the black strip of 1.1.0 was gone. **Not tested:** other wearers and fits (one person, one fit, two sweeps; the numbers are in `docs/fov_sweeps/`), HUD corners in other games, frame time. The two eyes differ (right eye 44 degrees outward and 28 toward the nose); a rectangle per eye would save about 13 % more but needs a headset app that declares a box per eye, which this release does not have. Send a sweep (`bench\xr_probe.exe`, `docs/FOV_CALIBRATION.md`) if you want yours included.

Frame generation needs an NVIDIA RTX GPU (Turing or later). Use at your own risk, see the README.
