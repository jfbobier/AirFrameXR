# AirFrameXR 1.1

Everything in [1.1 pre-release](v1.1.0-pre.md) and [1.1.1 pre-release](v1.1.1-pre.md) (the field of view for the game set from the streamer, the left-handed desktop mirror, the game fps lock and the frame pacing fix), plus:

- **Measured field of view for the Apple Vision Pro.** The Vision Pro profile now carries values measured with a sweep on the headset instead of a traced grid: **0.71 / 0.59 / 0.61 / 0.57** (outer / inner / upper / lower tangents, 35.4 / 30.5 / 31.4 / 29.7 degrees), no safety margin, one rectangle for both eyes. The Advanced picture and FOV settings window's button "Use the Apple Vision Pro's measured values" fills them. Render quality in the profile is **0** (no oversampling): the game renders at the smallest size that covers the rectangle, about a quarter of the pixels of the headset's declared view (computed from the areas; the previous values rendered about half), at the same sharpness per degree; the slider raises it if you want supersampling. Still a button, not a default: nothing is restricted until you press it or tick the override.
- **How it was measured** (`docs/FOV_CALIBRATION.md`, `docs/AVP_FOV.md`, data in `docs/fov_sweeps/`): a dot drifts outward along 24 rays per eye and the wearer clicks when it has gone, eyes free to follow it (the gaze a game is played with). The window is what one person sees, larger of the two eyes per direction; the 3 degree margin of the first estimate is gone. `bench\xr_probe.exe` gained the sweep and outline modes used for it (`XR_PROBE_FOVGRID=sweep|outline`) and `harness/fov_calibration.py` turns sweep files into the coverage / savings curve.
- Version 1.1.0 is the release number; 1.1.1-pre was a pre-release of the same line.

**Not tested:** the calibrated values were measured on **one person, one fit** and checked only by drawing the rectangle on the headset (it looked like a good fit); they have **not been played in a game** yet, so check the corners (HUD, intro screens) for black on your own fit and loosen an edge in the Advanced window if you see any. Gains are computed from areas, not measured as frame time. The visionOS app is unchanged by this release (a branch that declares the same rectangle itself is not built). Other wearers and other fits can differ: send a sweep if you want yours included (the sweep tool is in the package; instructions in `docs/FOV_CALIBRATION.md`).

IPC version 35: host, shim and package must come from the same build. Frame generation needs an NVIDIA RTX GPU (Turing or later). Use at your own risk, see the README.
