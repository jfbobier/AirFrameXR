# AirFrameXR 1.2.0

Everything in [1.1.1](v1.1.1.md), plus the field-of-view work of 2026-10-29 (`docs/FOV_PIPELINE_OPTIM.md`, `docs/FOV_CLIENT_CEILING.md`, `docs/AVP_FOV.md`). Pairs with the
**visionOS client 1.2.0** (fork `kteque/alvr-visionos`, tag `v1.2.0`); releases of the two are numbered together from now on.

- **A calibrated field of view by default.** The Vision Pro profile carries the rectangle measured on the author over three sweeps (eyes following and fixed, two fits) and
  read on the grid: **0.97 / 0.71 / 0.69 / 0.63** (outer / inner / upper / lower tangents, 44.1 / 35.4 / 34.6 / 32.2 degrees), the rectangle that covers 99 % of what the author sees.
  The wizard now applies it when it uses the profile, so games render 26 % fewer pixels than an unrestricted game on the AirFrameXR client (62 % fewer than on the stock app)
  with a sliver of black at the far outer and lower corners only. The Advanced window shows and changes it; the author's own 100 % set is 1.00 / 0.71 / 0.73 / 0.66.
- **The visionOS client 1.2.0** declares a per-edge **ceiling** (1.03 / 0.79 / 0.75 / 0.86, about 1.05 / 0.80 / 0.76 / 0.87 as the streamer sees it) instead of a fixed window, so
  the rectangle above can be raised on the PC without a client build (the calibration found a second wearer needing 0.80 at the bottom); the hand click is **visionOS's own pinch
  gesture** (the skeleton distance missed real pinches and clicked when a hand was turned over); and the picture is **black outside the frame** whatever the chroma key (the room
  used to show past the frame's edge). The TestFlight workflow gained an opt-in step that revokes the signing certificates earlier runs created, for Apple's cap.
- **The FoV grid ships in the package**: `bench\fovgrid.bat` shows a head-locked grid in true angles through AirFrameXR like a game, with a white border at the edge the
  headset declares, to see how much of the picture your headset shows and tune the field-of-view fields; `fovgrid.bat o,i,u,l` draws a rectangle (known defect: too faint on the
  Vision Pro, fix owed). The calibration bundle (`tools/fov_calibration_bundle`) runs the fixed-gaze pass after the following pass.
- **The render quality slider's pixels now reach the stream.** Its top is the unrestricted pixel count spent on the rectangle (about 1.1 x 1.2 linear here), and the compose pass
  used to read that denser render with one bilinear tap, skipping most of it; it now averages up to 3 x 3 taps over each output pixel's footprint. Not yet judged by eye.
- **"Fit the stream to the headset's window"** (Advanced, `video.stream_fit_window`, off by default): the stream frame sized to the box the headset declares at the density of
  the resolution you saved. Measured on an RTX 3080 Ti with the client declaring the rectangle itself: 30 % fewer pixels on every stage, encode 11.3 -> 8.4 ms foveated and
  20.2 -> 15.4 ms full frame, frame generation -30 %. With the 1.2.0 client, which declares the ceiling, it saves about 6 %; the 30 % needs the client to declare the wearer's
  rectangle (a later step). With the fit on, the render quality slider's right end is the saved resolution (IPC version 36).
- **What the pipeline will do** (Advanced, under the FoV fields): the stage sizes the settings imply (game render, stream frame, encoded frame, NVENC strips) and a warning when
  split-frame encoding will not engage: NVENC's automatic mode splits only frames 2112 rows or more with the P1-P4 low-latency presets, so a foveated frame only splits in the
  forced mode, which is the default. **Frame pipeline** in Game statistics: each run's record carries what every stage did (sizes, strips expected and seen, encode p50 / p95,
  foveation-pass and compose times), drawn as a row of tiles. The host writes `config\airframexr_gpu.json` (GPU, driver, NVENC engines).
- The "override saved for another headset" guard keys on the headset's name, so a saved calibration survives a client that declares another box.

Lab (RTX 3080 Ti and the author's 5090): the FoV scenarios old and new and the OpenXR chain PASS on IPC 36; the launcher's pipeline model equals the Python oracle on 148 cases;
the GUI matrix rows PASS. Field (5090 + Vision Pro, 2026-10-29): the ceiling client declared the predicted box, the run record's pipeline block worked (3 strips seen, encode
7.55 ms p50, compose 0.34-0.52 ms, decode 6.9 ms), the rectangle was checked on the grid. **Not on a headset**: the fitted stream's picture, the filtered compose pass by eye, the
pinch-gesture click in a game. IPC version 36: host, shim and package must come from the same build. Use at your own risk, see the README.
