# VisionALVR 0.5

Streamer for ALVR headsets (Apple Vision Pro, Quest 3), NVIDIA GPUs with NVENC API 12.2 or later. Still young software, test at your own risk:
it registers this folder as your OpenXR runtime and adds a firewall rule (both reversible from the launcher).

## Tested on

RTX 5090 with an Apple Vision Pro (ALVR visionOS app 20.14.x, 90 and 100 Hz), including hours-long sessions with frame generation and DLSS motion
vectors; a Quest 3 (Meta-store ALVR client) with 0.4's frame generation; automated tests, including the new stability harness, on an RTX 3080 Ti
laptop. NVIDIA only, end to end. The Windows desktop mirror is new and only lightly tried on a headset.

> **Vision Pro: a plain green screen when the headset connects is normal** (the idle frame while no game runs). Set the ALVR app's chroma-key colour
> to pure green (#00FF00) and you see your room between games.

## New in 0.5

- **The windows.** Double-click `VisionALVR.exe` and pick a tool from the launcher: **Streamer** (live tiles for fps, bitrate, latency split, loss;
  display settings; frame generation; Recenter and a recenter key, End by default), **Logs and performance** (one record per game with its last
  sessions, install or remove the DLSS motion-vector DLL per game, export a log zip), **Diagnose** (the wizard's checks on your current settings)
  and the **Setup wizard**. The launcher also switches the OpenXR runtime back and forth, reviews OpenXR layers that capture controllers, and reviews
  firewall rules. The windows scale from 1080p laptops to 4K at 100-200 %.
- **Game audio without a cable.** The host captures the game's sound with Windows' process loopback: nothing to install, the default output is left
  alone, games started as administrator (UEVR, mods) are captured too. The VB-CABLE route stays as a fallback in the advanced settings. The wizard
  plays the Littlest Tokyo music to test it. Needs Windows 10 version 2004 or newer.
- **Optional desktop mirror** between sessions (off by default): the Windows desktop floats in front of you and your hand is the mouse. New and
  experimental.
- **Windows power plan** and the **import of a working ALVR session.json** from the streamer's advanced settings.
- **Debug logging is off by default**; a debug package says so in its name and window titles.

## Sturdier: found by the new stability harness

A fault-injection and soak harness (`harness/stability/`, optional, documented in the README) was built from a real failure: a long Gears of War
E-Day session stopped streaming to the headset until frame generation was turned off. Reproduced in the lab and fixed:

- **Frame generation no longer deadlocks when the headset's tracking goes quiet.** Without a fresh head pose it used to send nothing, and the
  visionOS client only sends tracking while frames reach it, so a hiccup of a few seconds could become minutes without a picture. After 100 ms
  without a pose the host now sends frames stamped with the last real sample, as the generation-off path does. A 5 s silence of the uplink cost 61 s
  before and 0.1 s now; a 30 s host freeze cost 86 s and now costs the freeze itself.
- **A stalled streamer window can no longer freeze the host.** The host used to block on its output while the window did not read it (a dialog, a
  busy UI thread): a 30 s stall stopped the stream for 27 s. Events now go through a bounded queue.
- **A watchdog names stalls** (the process not running, the main loop, tracking, frames) in the log, and the log carries a memory line every 30 s
  (host RAM and handles, free RAM, GPU memory, the host's VRAM against its budget), even with debug logging off.
- Smaller: the per-game "releases late" counter no longer wraps after a game restart, and the eye-height line is logged at most once a second.

Lab results at the Vision Pro's size: the host holds about 1.9 GB of RAM and 2.0 GB of VRAM; squeezing the PC to 1.8 GB of VRAM or 2.3 GB of RAM
is survived; vector loss, re-created vector textures and garbage vectors cause no stall, error or growth; a 15-minute soak with seeded events
(settings, generation toggles, tracking blackouts, host and headset freezes, audio device changes) showed flat memory.

## DLSS motion vectors

The zip carries the extractor DLL as `DLSSMotionVectors\dxgi.dll`, built from the fork commit this build's shim mirrors (the C interface is
`DLSSVEC_*`: replace any older copy in a game folder). Copy it next to the game's real executable, renamed `winmm.dll`, `version.dll`,
`dbghelp.dll`, `winhttp.dll` or `wininet.dll` if another mod owns `dxgi.dll`, or let the Logs and performance window do it. GPL-3.0, source at
<https://github.com/jfbobier/OptiScaler-DLSSMotionVectorExtractor>. Not compatible with Luke Ross's R.E.A.L. VR mods or anti-cheat titles.

## Upgrading from 0.4

Unzip over a new folder, run `VisionALVR.exe`. Records from 0.4 (`config\games.json`) are not carried over. Replace the motion-vector DLL in any
game folder that has an older one.
